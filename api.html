hipObjError_t hipObjInit(hipObjConfig_t *config)#

Initialize the hipObject library.

Opens the RDMA device, selects the closest NIC to the GPU, and prepares internal state. Must be called before any other hipObj* function.

Thread safety

Serialized: runs one at a time with the other serialized functions, and returns hipObjInvalidValue if called from a callback. See Thread Safety.

Parameters:

config – Pointer to configuration struct

Returns:

hipObjError_t

hipObjError_t hipObjShutdown(void)#

Shut down the hipObject library.

Releases all RDMA resources. All registered buffers are implicitly deregistered.

A staging buffer that a copy that timed out may still use (see hipObjBufSync()) isn’t freed.

Thread safety

Serialized: runs one at a time with the other serialized functions, and returns hipObjInvalidValue if called from a callback. See Thread Safety.

struct hipObjOps_t#
#include <hipobj.h>

Callback struct for S3 SDK integration.

The application provides these callbacks so that hipObject can inject RDMA tokens into S3 requests and receive RDMA reply tags from the server. This mirrors cuObject’s CUObjOps_t pattern.

The callbacks run while hipObject holds its API lock, so they can’t call serialized functions; see Thread Safety.

Thread Safety#

hipObject can be called from any number of threads. Each function’s documentation says which of these it is:

  • Serialized functions use the library’s state: whether it’s initialized, the registered buffers, and the RDMA connection. They run one at a time across the whole process. Each one takes a library-wide lock and holds it until it returns, so a serialized call waits for the one in progress, on any thread, to finish.

  • Concurrent functions don’t use the library’s state. They can be called from any thread at any time, including while a serialized function runs and from a callback. As with any C function, calls that run at the same time mustn’t share a buffer that one of them writes to, or a token that one of them releases.

Since serialized calls run one at a time, only one transfer is in progress at a time, and calling hipObject from more threads doesn’t move data any faster. A call can also wait a long time for another thread’s transfer, which holds the lock for as long as the transfer takes: while the application’s callbacks send the S3 request and wait for the response, while hipObject copies the buffer through host memory (for a buffer that the NIC can’t reach directly), and while it waits for the RDMA transfer to complete.

hipObjShutdown() waits for the serialized call in progress to finish. Calls made after it, on any thread, that need an initialized library fail with hipObjNotInitialized until hipObjInit() is called again.

Callbacks. hipObjGet() and hipObjPut() run the hipObjOps_t callbacks with the lock held. A callback can call concurrent functions. If it calls a serialized function, that function returns hipObjInvalidValue instead of waiting for a lock its own thread holds. A callback also mustn’t wait for another thread that’s calling a serialized function, since that thread is waiting for the lock: neither can continue, and hipObject can’t detect it.

Transfers made of several calls. The lock covers one call, not a sequence of calls. A transfer that the application drives itself, with hipObjGetRdmaToken(), its own S3 request, and hipObjBufSync(), is several calls, and other threads’ calls can run between them. hipObject uses one RDMA connection for every transfer, so the application must make sure that such a transfer doesn’t overlap any other transfer, on any thread.

Serializing the library is how hipObject works now, not a promise: a later release may run transfers concurrently.

Thread safety

hipObjError_t hipObjBufRegister(void *devPtr, size_t size)#

Register a GPU buffer for RDMA transfers.

Exports the GPU buffer via dmabuf and registers it with the RDMA NIC. Maximum 4 GiB per registration. The buffer must lie within a single HIP allocation: returns hipObjInvalidValue if it runs past the end of the allocation that holds devPtr.

Thread safety

Serialized: runs one at a time with the other serialized functions, and returns hipObjInvalidValue if called from a callback. See Thread Safety.

  • devPtr – Pointer returned by hipMalloc

  • size – Size of the buffer in bytes

hipObjError_t hipObjBufRegisterHost(void *hostPtr, size_t size)#

Register a host buffer for RDMA transfers.

Registers user-owned CPU RAM, such as a buffer allocated with malloc() or hipHostMalloc(), with the RDMA NIC. hipObject does not allocate or free the host buffer. Maximum 4 GiB per registration.

Data Transfer (GET / PUT)#

hipObjError_t hipObjBufSync(void *devPtr, size_t size, off_t offset, int direction)#

Stage a registered buffer between device and host memory.

When a device pointer cannot be registered with the NIC directly (no dmabuf support, or a fabric with no peer-to-peer path to the GPU), hipObjBufRegister() registers a host staging buffer instead and the peer’s RDMA reads and writes land there. Callers driving a transfer through hipObjGetRdmaToken() must therefore call this with HIPOBJ_SYNC_TO_HOST before a PUT and HIPOBJ_SYNC_TO_DEVICE after a GET. It is a no-op, reporting success, for a directly registered buffer; hipObjGet() and hipObjPut() do it themselves.

When this returns hipObjSuccess, the copy has finished. If the copy doesn’t finish within the staging timeout (the HIPOBJ_STAGE_TIMEOUT_MS environment variable), this returns hipObjInternalError and leaves the copy running. It can still read or write the buffer after this returns. Until it finishes, hipObject keeps the staging buffer it uses, and the buffer can’t be used: hipObjGet(), hipObjPut(), hipObjBufSync(), and hipObjGetRdmaToken() return hipObjBusy for it, and hipObjBufDeregister() returns hipObjBusy and leaves it registered. Once the copy has finished, the buffer can be used and deregistered again. If it never finishes, the staging buffer is never freed.

hipObject doesn’t wait for GPU work that uses the buffer, on any stream. Before HIPOBJ_SYNC_TO_HOST, make sure that the GPU work that writes the buffer has finished, for example with hipStreamSynchronize(). Before HIPOBJ_SYNC_TO_DEVICE, make sure that no GPU work that reads or writes the buffer is still running.

Thread safety

Serialized: runs one at a time with the other serialized functions, and returns hipObjInvalidValue if called from a callback. See Thread Safety.

hipObjError_t hipObjGet(hipObjHandle_t handle, void *devPtr, size_t size, off_t offset, hipObjOps_t *ops, void *ctx)#

GET: fetch an S3 object into a registered buffer via RDMA.

The server performs an RDMA WRITE to push data into the registered buffer, starting offset bytes into it. The bytes from offset to offset + size must lie inside the buffer. hipObject doesn’t send an object offset; the request the callbacks make selects the part of the object to fetch.

Make sure that no GPU work that reads or writes the buffer is still running when you call this. When it returns hipObjSuccess, the data is in the buffer.

For a buffer that’s staged through host memory (see hipObjBufSync()), if the copy into the buffer doesn’t finish within the staging timeout (the HIPOBJ_STAGE_TIMEOUT_MS environment variable), this returns hipObjInternalError and leaves the copy running. It can still write the buffer after this returns, and until it finishes, the buffer can’t be used or deregistered (see hipObjBufSync()).

Thread safety

Serialized: runs one at a time with the other serialized functions, and returns hipObjInvalidValue if called from a callback. See Thread Safety.

Parameters:

  • handle – S3 object handle (from application)

  • devPtr – Registered GPU or host buffer

  • size – Number of bytes to transfer

  • offset – Byte offset into the registered buffer

  • ops – S3 SDK callbacks

  • ctx – User context passed to callbacks

Returns:

hipObjError_t

hipObjError_t hipObjGetRdmaToken(const void *devPtr, size_t size, int op, char **outToken)#

Mint a hex-encoded RC RDMA token for a registered buffer.

The caller must release *outToken with hipObjPutRdmaToken(). op is HIPOBJ_RDMA_OP_PUT or HIPOBJ_RDMA_OP_GET (reserved).

Returns hipObjBusy while a staging copy of the buffer that timed out is still running (see hipObjBufSync()).

Thread safety

Serialized: runs one at a time with the other serialized functions, and returns hipObjInvalidValue if called from a callback. See Thread Safety.

hipObjError_t hipObjParseRdmaReply(const char *reply, size_t replyLen, int *httpCode)#

Parse an x-amz-rdma-reply header value.

On success writes the HTTP-style reply code (200, 204, 206, 501) to httpCode.

Thread safety

Concurrent: can be called from any thread at any time, including from a callback, as long as calls that run at the same time don’t share a buffer that one of them writes to or a token that one of them releases. See Thread Safety.

hipObjError_t hipObjPut(hipObjHandle_t handle, const void *devPtr, size_t size, off_t offset, hipObjOps_t *ops, void *ctx)#

PUT: store a registered buffer to an S3 object via RDMA.

The server performs an RDMA READ to pull data from the registered buffer, starting offset bytes into it. The bytes from offset to offset + size must lie inside the buffer. hipObject doesn’t send an object offset; the request the callbacks make selects where the data goes in the object.

hipObject doesn’t wait for GPU work that writes the buffer, on any stream. Make sure that it has finished, for example with hipStreamSynchronize(), before you call this.

For a buffer that’s staged through host memory (see hipObjBufSync()), if the copy out of the buffer doesn’t finish within the staging timeout (the HIPOBJ_STAGE_TIMEOUT_MS environment variable), this returns hipObjInternalError and leaves the copy running. It can still read the buffer after this returns, and until it finishes, the buffer can’t be used or deregistered (see hipObjBufSync()).

Thread safety

Serialized: runs one at a time with the other serialized functions, and returns hipObjInvalidValue if called from a callback. See Thread Safety.

Parameters:

  • handle – S3 object handle (from application)

  • devPtr – Registered GPU or host buffer

  • size – Number of bytes to transfer

  • offset – Byte offset into the registered buffer

  • ops – S3 SDK callbacks

  • ctx – User context passed to callbacks

Returns:

hipObjError_t

Release a token allocated by hipObjGetRdmaToken()

Thread safety

Concurrent: can be called from any thread at any time, including from a callback, as long as calls that run at the same time don’t share a buffer that one of them writes to or a token that one of them releases. See Thread Safety.

hipObjError_t hipObjTokenClientNic(const char *token, char *nicIp, size_t nicIpLen)#

Extract client NIC IPv4 from a minted RDMA token.

Writes a dotted-quad address into nicIp when the token GID carries an IPv4-mapped RoCEv2 suffix. Returns hipObjSuccess with an empty string when no address is encoded.

Thread safety

Concurrent: can be called from any thread at any time, including from a callback, as long as calls that run at the same time don’t share a buffer that one of them writes to or a token that one of them releases. See Thread Safety.
